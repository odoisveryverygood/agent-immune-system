# Build plan — four people

Adapt timing to the time remaining. Integration comes before visual polish.

## First 30 minutes

- All: read the wire contract and claim a lane/branch.
- Person 1: freeze Pydantic models and event envelope; implement a fixture API stub.
- Person 2: prove the target tool can run in the actual OpenShell environment. Start setup immediately; record blockers.
- Person 3: confirm Crusoe/Nemotron and You.com credentials are available without exposing values.
- Person 4: render the example event stream with a visible fixture badge.

## First working slice

- Target accepts a clearly labeled deliberately vulnerable $0 order.
- Deterministic oracle records why `0 < 45000` violates the trusted policy.
- API streams actual persisted events; UI displays the tool receipt and violation.
- No recursion or repair is claimed before this slice works.

## Recursive slice

- Investigator observes the violation and creates narrower child investigations.
- At least one child creates a justified grandchild through the same runner.
- All descendants consume one root budget; depth/concurrency/deadline limits work under failure.
- Failed/malformed provider calls remain failures with an explicit error state.

## Repair slice

- Research returns actual relevant source excerpts with URLs.
- Nemotron reviews actual target evidence and identifies the failed requirement.
- Repair agent proposes a schema-valid policy patch.
- Executor applies it in the sandbox; exact attack replay is blocked.
- Held-out attacks run after the patch is frozen; legitimate full-price and authorized-discount orders still succeed.
- If either malicious or legitimate behavior fails, report incomplete repair.

## Final hour

- Stop adding features. Integrate reviewed PRs only after human approval.
- Run a clean end-to-end verification and record live/fixture modes.
- Rehearse a 3-minute demo and record an accessible 1-minute video.
- Show the recursive task tree, a real baseline failure, repair result, held-out results and limitations.
- Check the current event rules before submission, especially judging, eligibility and required materials.

## Definition of done

An unfamiliar teammate can launch the app with documented commands, start one run, see evidence-driven nested delegation, observe a policy violation, apply a constrained repair and inspect replay/held-out/legitimate results. Each sponsor claim has execution evidence. Everything else remains explicitly marked unimplemented or unverified.

## Cut first

Refunds, multiple stores, authentication, real commerce, autonomous deployment, arbitrary code rewriting, decorative agent personalities and extra dashboards. Keep one compelling checkout repair demonstration.
